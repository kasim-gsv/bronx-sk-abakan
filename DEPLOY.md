# Деплой и превью для клуба

Коротко: сайт — это Next.js с серверными функциями (запись на занятия, админка,
база SQLite). Поэтому статический хостинг (GitHub Pages) не подойдёт, а
бесплатные платформы дают **эфемерный диск**: база живёт до перезапуска.
Для показа владельцу этого достаточно, для работы клуба — нет.

## Что выбрать

| Платформа | Подходит для | Ограничения |
| --- | --- | --- |
| **Render, free** (рекомендую для превью) | Показать сайт владельцу по ссылке | Засыпает без трафика, диск сбрасывается при редеплое, база теряет заявки/записи |
| **Vercel Hobby** | Быстрый превью-деплой | По правилам Vercel Hobby — только некоммерческое использование; клуб коммерческий. Плюс нет постоянного диска |
| **Render/Koyeb с платным диском** | Небольшой рабочий сайт | От ~$7/мес, диск сохраняет SQLite |
| **VPS (Timeweb, Beget и т.п.)** | Настоящий запуск клуба | Нужна настройка сервера, зато SQLite и данные под контролем, от ~150–300 ₽/мес |

Цены и условия бесплатных планов меняются — проверяйте при регистрации.

## Вариант 1: Render (превью по ссылке)

1. Зарегистрируйтесь на [render.com](https://render.com) (нужен GitHub-аккаунт
   или e-mail).
2. Загрузите проект в GitHub (репозиторий может быть приватным).
3. В Render: **New → Blueprint**, выберите репозиторий — Render прочитает
   `render.yaml` и создаст сервис `bronx-preview`.
   Либо вручную: **New → Web Service**, runtime **Node**,
   Build Command `npm ci --include=dev && npm run build`, Start Command
   `npm start`.
4. На **первом** деплое сразу задайте переменные (Render передаёт их и в сборку,
   и в рантайм — `NEXT_PUBLIC_SITE_URL` нужен именно на этапе сборки, иначе
   canonical и sitemap запекутся с `localhost`):
   - `NEXT_PUBLIC_SITE_URL` = `https://<имя-сервиса>.onrender.com`
   - `SEED_DEMO` = `1` (добавит 3 демо-занятия при пустой базе)
5. Передеплойте (**Manual Deploy → Deploy latest commit**) — ссылка готова.

Проверить после деплоя:

- `/` — главная, `/schedule` — занятия, `/privacy` — политика
- отправка формы заявки: она сохранится в базе, админ увидит её в `/admin`
- запись на занятие и отмена по ссылке

## Вариант 2: Docker (VPS, Koyeb, любой контейнерный хостинг)

```bash
docker build -t bronx .
docker run -p 3000:3000 \
  -e AUTH_SECRET="$(openssl rand -hex 32)" \
  -e NEXT_PUBLIC_SITE_URL="https://bronx.example.ru" \
  -e DATABASE_PATH="/app/data/bronx.db" \
  -v bronx-data:/app/data \
  bronx
```

Том `bronx-data` сохраняет базу между перезапусками. На VPS поставьте перед
приложением Caddy или nginx с HTTPS.

## Переменные окружения

| Переменная | Обязательно | Смысл |
| --- | --- | --- |
| `AUTH_SECRET` | да, в production | Подпись сессий, 32+ символа. Без него сервер не создаст сессию |
| `NEXT_PUBLIC_SITE_URL` | да | Публичный адрес: canonical, sitemap, OG-теги |
| `DATABASE_PATH` | нет | По умолчанию `./data/bronx.db` |
| `SEED_DEMO` | только для превью | `1` — добавить демо-занятия при пустой базе |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | для уведомлений | Заявки уходят в Telegram; без них сохраняются только в базе |
| `TELEGRAM_LOGIN_CLIENT_ID`, `TELEGRAM_LOGIN_CLIENT_SECRET` | для входа через Telegram | Client ID/Secret из @BotFather → Login Widget |
| `ADMIN_TELEGRAM_IDS` | для админки | Telegram ID администраторов через запятую |
| `ALLOW_DEV_LOGIN` | нет | `1` — тестовый вход в production. Только для закрытого превью: любой получит права администратора |

## Чек-лист перед публичным запуском

- [ ] `AUTH_SECRET` — случайный, не из примера
- [ ] `ALLOW_DEV_LOGIN` не задан (или `0`)
- [ ] `SEED_DEMO` убран, демо-занятия удалены через админку
- [ ] Настроен Telegram-бот: заявки приходят в чат
- [ ] Настроен вход через Telegram и `ADMIN_TELEGRAM_IDS`
- [ ] В `/privacy` вписаны реквизиты оператора (ИП/ООО, ИНН, адрес)
- [ ] Фотографии и логотип заменены, расписание и цены заполнены
- [ ] Настроено резервное копирование `data/bronx.db` (на VPS — cron + `sqlite3 .backup`)
- [ ] Домен и HTTPS, `NEXT_PUBLIC_SITE_URL` указывает на боевой адрес

## Резервное копирование SQLite (VPS)

```bash
sqlite3 /path/to/data/bronx.db ".backup '/backup/bronx-$(date +%F).db'"
```

Копировать работающий файл `cp` нельзя — база в режиме WAL, копия может
оказаться битой. Только `.backup` или остановка приложения.
